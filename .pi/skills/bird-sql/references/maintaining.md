# 维护这个 skill 时（做题时不用读）

> 从 `SKILL.md` 搬出来的 —— 那里要常驻上下文，这里只在**改 skill** 时读。

## 维护约定（改这个 skill 时）

1. **SKILL.md 只放流程**。新增知识一律按第 7 步的表归位，**不要往这里塞细节**。
2. ⛔ **库特有的事实不落盘**（没有 `db/<库>.md` 这个落点了）：它们**随库消失**，
   写下来只会在别的库上被误用。能留下的必须是**跨库成立的规则**（`traps.md` / `checklist.md`）。
3. 每条规则都要带**实测题号 + 数字**（如"387: 187→10"），否则以后无法验证。
4. 归纳规则前过一遍：**这条能让我写出更接近金标的 SQL 吗？** 只能复现一个 bug 的不收。
5. **发现了反例就立刻改，不留自相矛盾的条款**（`NULL 排序`、`european_football_2 的 LIMIT 1`
   都曾经写反过 —— 各被 2–3 道题同时证伪）。
6. 改完在**没做过的题**上验证，别只在错题上验证（错题已经“见过答案”了）。
7. ⭐ **知识必须能被“推到决策点”**：新规则写进正文没人读 = 等于没写。写在 `references/*.md` 里的，
   就要用 `<!-- push step=N -->…<!-- /push -->` 包住（`brief` 会推它）——**唯一**的落点。
8. 宁可包住**现成小节**（零漂移），也不另写一份摘要（两份说法早晚不一致）。

### 如果下次又漏了规则，按这 3 条查

1. **漏的规则在哪个文件？** 如果它在 `casebook.md` 里 —— 那是记账本，**做题时本来就不会读**，
   说明它**没毕业**，立刻搬到 `traps.md` 或 `checklist.md`（库特有的事实则直接丢弃）。
2. **它是不是"陈述句"？**（"本库输出要 DISTINCT"）→ 改成**祈使句 + 检查点**
   （"⚠️ 交题前必查：输出列加 DISTINCT 了吗？"）。
3. **它是不是藏在长文件中间？** → 拆短，或提到该文件顶部。

### 📐 「不预写库知识」的硬约束

> 2026-10-02 实测（官方 test 成绩反向归因）：11 份手写库档案只在 **dev 的 11 个库**上有内容，
> 而隐藏 test 用的是 **dev 之外的另外 15 个库** ⇒ 档案在 test 上命中率**恒为 0**。
> 同期 dev→test 落差 −2.84 分，是同行（含旧 dev 组）里**最差**的一个 ⇒ 档案是"背了题库"。
> 结论：库级知识**不许落盘**，一律运行时现场查（`traps.md` ⓪-1 的五查）。
> 曾经存在的 11 份 `db/<库>.md` 手写档案与「惯例卡片」机制**已全部删除/废除**。

1. **`references/db/` 目录不许存在**（删了不要再建）。
2. **工具链不许写 `references/`**：`conventions --write-card` 已删除；references 是**只读**知识库。
3. **`brief` 不接受库名参数**；`runner/prompt.py` 的 `build_system()` **不接受 `db_id`**。
4. 库事实由 `runner/prompt.py` 的两层侦察现场取得：**低基数列全量取值**（去重值 ≤12 的列直接列全）
   + **题干/evidence 字面量反查**（命中给真值与计数，查不到显式写 `NOT FOUND`）；做题时用
   `bird_cols` / `bird_find` / `SELECT DISTINCT` 做同样的事。

## 📤 产物 ↔ 落点注册表（类①「无落点的产物」的唯一出处）

> 缺陷形态：文档写"你要产出 X 并写进 Y"，而 **Y 里从来没有 X、或 Y 根本不存在**
> （实测两例：第 0 步的"体检单"、被 4 处引用的"挂起清单"）。
> 判定法一句话：**声称产出的东西，去目标位置 `rg` 一次**。
> `tools/tests/check_docs.py` 按本表双向校验：SKILL.md 里**每个含「📤 产出」的步骤都必须在本表登记**，
> 且落点**真实存在**（路径存在；写 `## 小节` 的必须能在某个 references 文件里找到）
> —— 没登记的产出行 = 装饰。标了「不落盘」的产物按设计就不留文件（库知识不预写）。

| 步骤 | 产物 | 落点（真实容器） | 机器强制 |
|---|---|---|---|
| 第 0 步 | 库结构五查（表数/列名/JOIN 命中率/值域/NULL） | 瞬时（现场用完即弃，**不落盘** —— 见 `traps.md` ⓪-1） | ✗ |
| 第 0.5 步 | 值域侦察（低基数列全量取值 + 字面量反查） | 瞬时（`bird_cols` / `bird_find` 的输出） | ✗ |
| 第 1 步 | 题型 + evidence 口径划条 | 瞬时（下一步的输入；最终由第 4 步的 `--attrs` 逼成原文片段） | 部分（闸门 4） |
| 第 2 步 | 骨架名 | 瞬时（决定用哪个骨架的固定动作） | ✗ |
| 第 3 步 | 每个字面量的库内真值（拼写/大小写） | 瞬时 + `checklist.md` 12 勾选 | ✓（闸门 3） |
| 第 3.5 步 | 概念 → 候选列 → 裁决依据 | 瞬时（写进最终 SQL 的注释，**不落盘**） | 部分（闸门 4 要求原文可溯） |
| 第 4 步 | 最终 SQL | `work/answers_dev2025.json`（工具写）+ SQL 顶部 `/* shape */` | ✓（闸门 2 + 4） |
| 第 5 步 | 自检勾选 | `work/probe_log.jsonl` 的 `checks` 记录 | ✓（闸门 3） |
| 第 6 步 | 提交记录 | `work/answers_dev2025.json` + `work/probe_log.jsonl` | ✓（四道闸门） |
| 第 7 步 | 规则写回（**只收跨库成立的**） | `traps.md` / `checklist.md`（复盘账本 `casebook.md` 只记账） | 部分（check_docs + 当场 `rg`） |
| 任意步 | 挂起清单 | `audit` 错题明细（**不另设文件**，见 `diagnosis.md`） | ✗ |

**本轮之前的 11 类实例**（防止再次复发）：新写一句"产出 X 写进 Y"时，**先在本表加一行**，再动 SKILL.md。
