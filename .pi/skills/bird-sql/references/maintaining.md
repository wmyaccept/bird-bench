# 维护这个 skill 时（做题时不用读）

> 从 `SKILL.md` 搬出来的 —— 那里要常驻上下文，这里只在**改 skill** 时读。

## 维护约定（改这个 skill 时）

1. **SKILL.md 只放流程**。新增知识一律按第 7 步的表归位，**不要往这里塞细节**。
2. **`db/<库>.md` 的"必查"永远只有 3 条**：新坑进来，就要把旧的那条最没用的挤出去
   （否则又会变成"翻不到"的长文档）。
3. 每条规则都要带**实测题号 + 数字**（如"387: 187→10"），否则以后无法验证。
4. 归纳规则前过一遍：**这条能让我写出更接近金标的 SQL 吗？** 只能复现一个 bug 的不收。
5. **发现了反例就立刻改，不留自相矛盾的条款**（`NULL 排序`、`european_football_2 的 LIMIT 1`
   都曾经写反过 —— 各被 2–3 道题同时证伪）。
6. 改完在**没做过的题**上验证，别只在错题上验证（错题已经“见过答案”了）。
7. ⭐ **知识必须能被“推到决策点”**：新规则写进正文没人读 = 等于没写。写在 `references/*.md` 里的，
   就要用 `<!-- push step=N -->…<!-- /push -->` 包住（`brief` 会推它），或写进 `db/<库>.md` 的惯例卡片。
8. 宁可包住**现成小节**（零漂移），也不另写一份摘要（两份说法早晚不一致）。

### 如果下次又漏了规则，按这 3 条查

1. **漏的规则在哪个文件？** 如果它在 `casebook.md` 里 —— 那是记账本，**做题时本来就不会读**，
   说明它**没毕业**，立刻搬到 `db/<库>.md`、`traps.md` 或 `checklist.md`。
2. **它是不是"陈述句"？**（"本库输出要 DISTINCT"）→ 改成**祈使句 + 检查点**
   （"⚠️ 交题前必查：输出列加 DISTINCT 了吗？"）。
3. **它是不是藏在长文件中间？** → 拆短，或提到该文件顶部。

### 📐 库档案（`db/*.md`）的硬约束

> 这三条都是**实测踩出来的**（P20）：档案是"缓存"，缓存最容易出的错不是漏，而是**串味**——
> 把别的库的笔记、别的数据集的数字、已经作废的结论留在里面，读的人却当成现行事实。

1. **表头的 `simple EX` 必须标数据集**。表头那串数字来自**旧 dev（2024-06）的 simple 全量**，
   而惯例卡片来自 **dev2025** —— 两个数据集、两个口径，不标就会被当成"当前成绩"。
2. **正文里的题号必须是本库的题**（按 `dev2025` 编号）。引用别的库/别的数据集时**一律带前缀**
   （`minidev idx N` / `dev2025 idx N`）—— 同一个数字在不同数据集下是**不同库的题**，
   不带前缀就等于给出了一条无法核对的证据。
3. **提到本库没有的表/列，必须落在否定语境**（「没有」/「不成立」/`⛔ 已作废`/`no such column`）。
   正面陈述一句"spent → `transactions_1k.Price`"，读的人就会去 financial 里找一张不存在的表。
4. **必须有 `## 同义表`**（值层六问第 1 条 / checklist 8b 的落点）。没有可写的就写「无」，不许缺节。

`tools/tests/check_docs.py` 对这几条各有守卫（其中一条查「档案点名的表/列是否存在」）。

## 📤 产物 ↔ 落点注册表（类①「无落点的产物」的唯一出处）

> 缺陷形态：文档写"你要产出 X 并写进 Y"，而 **Y 里从来没有 X、或 Y 根本不存在**
> （实测两例：第 0 步的"体检单"、被 4 处引用的"挂起清单"）。
> 判定法一句话：**声称产出的东西，去目标位置 `rg` 一次**。
> `tools/tests/check_docs.py` 按本表双向校验：SKILL.md 里**每个含「📤 产出」的步骤都必须在本表登记**，
> 且落点**真实存在**（路径存在 / 档案里有该 `## 小节`）—— 没登记的产出行 = 装饰。

| 步骤 | 产物 | 落点（真实容器） | 机器强制 |
|---|---|---|---|
| 第 0 步 | 结构体检（表数/列数/JOIN 命中率） | `db/<库>.md` 的 `## 连接图与坑` | ✗（只在换新库时做） |
| 第 0.5 步 | 惯例卡片 | `db/<库>.md` 的 `## 惯例卡片`（工具写） | ✗（工具生成，天然可信） |
| 第 1 步 | 题型 + evidence 口径划条 | 瞬时（下一步的输入；最终由第 4 步的 `--attrs` 逼成原文片段） | 部分（闸门 4） |
| 第 2 步 | 骨架名 | 瞬时（决定用哪个骨架的固定动作） | ✗ |
| 第 3 步 | 本次要防的 3 条 | `db/<库>.md` 顶部必查（读）+ `checklist.md` 12 勾选 | ✓（闸门 3） |
| 第 3.5 步 | 概念 → 候选列 → 裁决依据 | 瞬时（决策记录）+ `db/<库>.md` 的 `## 同义表` | 部分（闸门 4 要求原文可溯） |
| 第 4 步 | 最终 SQL | `work/answers_dev2025.json`（工具写）+ SQL 顶部 `/* shape */` | ✓（闸门 2 + 4） |
| 第 5 步 | 自检勾选 | `work/probe_log.jsonl` 的 `checks` 记录 | ✓（闸门 3） |
| 第 6 步 | 提交记录 | `work/answers_dev2025.json` + `work/probe_log.jsonl` | ✓（四道闸门） |
| 第 7 步 | 规则写回 | `traps.md` / `checklist.md` / `db/<库>.md`（复盘账本 `casebook.md` 只记账） | 部分（check_docs + 当场 `rg`） |
| 任意步 | 挂起清单 | `audit` 错题明细 + `db/<库>.md` 实测小节（**不另设文件**，见 `diagnosis.md`） | ✗ |
